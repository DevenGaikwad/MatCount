# Faculty demonstration — MatCount / SEMS v2 RC2

This is a locally executable **academic release candidate**, not final faculty acceptance. Use the immutable `v2.0.0-rc.2` package and record `SOURCE_COMMIT.txt`. Internet may be needed for the first dependency installation. No cloud deployment is needed.

1. Before extraction, compare `(Get-FileHash .\MatCount_SEMS_v2_Offline_Faculty_Demo_FINAL_v2.0.0-rc.2.zip -Algorithm SHA256).Hash.ToLower()` with the separate `.zip.sha256` file. Stop on a mismatch. Extract into a **new** folder; do not extract over existing private configuration.
2. Check Windows 10/11 x64, Python 3.12, Node 24.19.0/npm 11.9.0, MySQL Community Server 8.4.11 and MySQL Workbench. Run `py -3.12 --version`, `node --version`, `npm --version`; verify MySQL with `SELECT VERSION()` in Workbench.
3. In a VS Code PowerShell terminal at the extracted project root, run `py -3.12 -m venv .venv`.
4. Install the frozen Windows dependencies: `.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-windows.lock.txt`. Then run `.\.venv\Scripts\python.exe -m pip check`.
5. Run `Push-Location frontend`, `npm ci`, then `Pop-Location`. This uses the committed npm lock; do not substitute `npm install` or a floating version.
6. Copy `.env.example` to `.env` and `frontend/.env.local.example` to `frontend/.env.local` only when those private files do not already exist. Fill the local values privately. Keep `DB_NAME=sems_db` and `NEXT_PUBLIC_SEMS_API_URL=http://127.0.0.1:8000/api`. Generate each local login hash with `.\.venv\Scripts\python.exe scripts/generate_demo_hash.py`; map it to the exact seeded USER email. Never commit or screenshot credentials/hashes.
7. For a **fresh empty** `sems_db`, execute complete Workbench scripts `00_database_setup.sql`, `01_schema.sql`, `02_indexes.sql`, `03_views.sql`, `04_routines.sql`, `05_triggers.sql`, `06_seed_data.sql`, then read-only `07_verification_queries.sql`. If a valued database already exists, use the verification guide first and do not reset or reseed it. Configure a dedicated local `sems_app` MySQL account with SELECT/INSERT/UPDATE/DELETE/EXECUTE on `sems_db`; normal application services must not run as root.
8. For the integration suite only, build a separate disposable database with `.\.venv\Scripts\python.exe scripts/build_database.py --database sems_test --user root`. The script prompts locally for the administrative password. Configure the test URL securely as described in [the Windows runbook](OFFLINE_SETUP_WINDOWS.md). Never point integration tests at `sems_db`.
9. Run the complete acceptance command: `.\scripts\final_acceptance.ps1`. A successful server-independent CI run does not replace this intended-host acceptance or the 20 MySQL cases.
10. In terminal 1 at the project root, run `.\.venv\Scripts\python.exe -m uvicorn api.main:app --host 127.0.0.1 --port 8000`. In terminal 2, run `Set-Location frontend` then `npm run dev -- --hostname 127.0.0.1 --port 3000`. Open `http://127.0.0.1:3000`. The API health URL is `http://127.0.0.1:8000/api/health`; inspect its database status as well as HTTP success.
11. Sign in with the private locally generated demonstration credentials. Existing seed identities include `admin@sems.local`, `faculty.vlsi@sems.local`, `assistant.vlsi@sems.local` and `student.vlsi@sems.local`.
12. Demonstrate Administrator master/approval access, Student own-lab request and price restrictions, Faculty own-lab review, and Lab Assistant permitted stock/transfer actions. Show both allowed and denied behavior, lab scope, persisted database effects and safe CSV outputs. Follow [the faculty guide](docs/FACULTY_DEMO_GUIDE.md) and [role matrix](docs/RBAC_PERMISSION_MATRIX.md); capture genuine proof only after execution.
13. In Workbench confirm the active database, 13 base relations, seven views, two triggers, PK/FK structure and a meaningful join. Execute the documented ETCS302 teaching scripts in their stated isolated schemas. Never execute reset, deadlock or DCL exercises against valued data. Follow [the Workbench guide](docs/MYSQL_WORKBENCH_EXECUTION_GUIDE.md).
14. Stop each service with **Ctrl+C in its own terminal**. Wait for termination before closing terminals. Optional fallback: `.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1 --server.port 8501`; stop it the same way. MySQL Workbench and the application independently use the same database.

Keep the original provenance ZIP and RC1 unchanged. This new bundle has its own filename, hash, dependency locks and validation report. See [dependency versions](DEPENDENCY_VERSIONS.md), [validation boundaries](VALIDATION_SUMMARY.md) and [baseline parity](docs/OFFLINE_FACULTY_DEMONSTRATION_BASELINE.md).
